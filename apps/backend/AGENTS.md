# ASP.NET Core backend

This is the v2 backend foundation (MAZ-51 onward). Use ASP.NET Core and PostgreSQL 18 with pinned SDK/provider/patch/image versions. Preserve `contracts/openapi.json`, ledger v4, sessions and legacy clients. Follow `docs/migration/postgresql.md`: SQLite is an import/rollback source, not the v2 runtime. Test real HTTP/PostgreSQL with atomic revisions, isolation, two-worker leases and import/recovery. The schema is EF Core: change it only through `dotnet ef migrations add` as described in `docs/migration/postgresql.md#changing-the-schema`, and keep raw SQL to its documented inventory. Run format/analyzers, build, unit/integration and contract checks. Root Expo guidance applies to the legacy app, not .NET here.

Use the standard controller-based startup in `src/Penny.Backend.Api/Program.cs`. Dependencies point inward: API/Persistence -> Application -> Domain. Follow the repository's `.agents/skills/dotnet-webapi-integration-testing` skill, adapting its examples to the existing `{error:string}` contract. Keep one shared real PostgreSQL fixture; use WebApplicationFactory (Kestrel for transport/lifetime checks), cancellation tokens and per-test isolation. Never introduce SQLite/in-memory stand-ins or silently skip missing containers.

Keep production projects under `src/` and test projects under `tests/`, including matching solution folders. Group code by responsibility inside projects: API Configuration/Contracts/Controllers/Errors/Middleware, Application Abstractions/Persistence, Domain Errors, and Persistence Configuration/Health/Migrations/Schema. Test support belongs in Infrastructure/Probes, with tests grouped into Contracts/Controllers/Http/Migrations or Architecture/Configuration. Match namespaces to folders and use one named type per file; keep Program.cs as the composition entry point.

Name every test `whenCondition_MethodOrFunctionOrFlow_ShouldExpectedOutcome`, for example `whenDatabaseUnavailable_Readiness_ShouldReturnServiceUnavailable`. Use the lowercase `when` prefix and exactly three underscore-separated sections. This user-requested convention takes precedence over the skill's example test names.

Use `bash apps/backend/dotnet.sh` from the repository root for all .NET commands so caches and temporary files stay in the project. SDK, centralized packages, lockfiles, CSharpier and the PostgreSQL image digest are pinned. Run tool/locked restore, CSharpier check, `format analyzers --verify-no-changes --no-restore`, Release build and `test --solution Penny.Backend.slnx` (Microsoft.Testing.Platform), plus root npm lint/typecheck. See README.md for exact commands.

Migrations run only via the explicit `migrate` command with separate migration credentials and the database advisory lock. Runtime readiness must check connectivity/schema/extension compatibility without changing data. Keep credentials, SQL parameter values, exception details and financial text out of logs. MAZ-52 owns product schema/import; MAZ-121 owns search projections/indexes. Do not expose unfinished product endpoints or replace the legacy deployment in this foundation.
