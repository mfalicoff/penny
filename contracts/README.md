# Shared contracts

`openapi.json` is OpenAPI 3.1, contract version 1.5.0 (MAZ-61 adds optional APNs `provider`/`environment` fields to `PushDevice`; Node rejects APNs tokens, .NET accepts both). Legacy compatibility routes are marked `x-implementation: legacy`; `/api/ready` is `backend-foundation` (MAZ-51), `POST /api/auth/password-reset` is `backend` (implemented only by .NET, MAZ-123), and search v1 `POST /api/v1/search/transactions` is `backend` (.NET only, MAZ-121). The foundation serves health/info/readiness only; the other legacy routes are still supplied by Node pending their port. Preserve v4 ledger/session/ID/revision compatibility regardless of PostgreSQL storage.

- `fixtures/http-journey.json`: sanitized register/ledger/409/shared-projection examples exercised through real legacy HTTP/SQLite.
- `fixtures/ledger-upgrades.json`: validated v1–v4 input and normalized v4 output.
- `fixtures/parity-cases.json`: cents, personal/shared rounding, anchor dates and three-way merge expectations.
- `fixtures/shared-splits.json`: golden equal/exact/percentage split cases (integer cents, remainder allocation, zero shares, rejected totals) consumed by `tests/core/households-domain.test.ts` and the .NET `HouseholdSplitsTests`.
- `fixtures/settlement.json`: golden monthly balance and suggested-reimbursement cases (partial/complete settlement, ignored months and deleted expenses, zero shares, tie-breaks, largest totals, rejected balances) produced by the TypeScript `calculateMonthlyBalances`/`suggestReimbursements` and consumed by `tests/core/households-domain.test.ts` and the .NET `MonthlySettlementTests`.
- `fixtures/search-cases.json`: legacy local substring and pending cases (the current app), the shared search normalization (`foldCases`, checked by `tests/core/search-normalization.ts` and the .NET `SearchTextTests`), a server ledger with title/text/typo/filter/sort/pagination cases (`lexicalCases`, `paginationCase`) and English/French/mixed meaning cases (`meaningCases`) run by the .NET real-PostgreSQL `SearchFixtureTests`, plus valid and invalid request examples and a response example. Exotic characters are written as `\u` escapes.
- `fixtures/storage-mapping.json`: exact integer/time/binary/JSON encodings and import blockers for MAZ-52/62; no importer is supplied here.
- `fixtures/money.json`, `fixtures/recurrence.json`, `fixtures/merge-conflicts.json` (MAZ-62): golden integer-cent parsing/shares/bounds, anchored recurrence and three-way offline merge cases, **generated** from the legacy TypeScript rules by `npm run fixtures:generate` (`scripts/fixtures/generate-golden.ts`); never edit them by hand.
- `fixtures/month-totals.json` (MAZ-136, generated the same way from `src/domain/summary.ts`): Left to spend (recorded) versus Projected around today. Income dated after the person's local date is expected and counts toward Projected only, until its date; `todayCases` turn an instant and an IANA time zone into that date. Scope: income only; future-dated expenses and investments stay recorded (MAZ-139). Consumed by `tests/core/golden-fixtures.test.ts` and the Swift `ReportTests`.
- `fixtures/full-stack-seeds.json` (MAZ-62): deterministic seed scenarios (`empty`, `searchable-household`, `differential`) run over HTTP by `scripts/test-env/seed.mjs` and by the .NET `FullStackSeedTests`, with search expectations, pending offline edits and legacy-comparison probes.
- `fixtures/redesign-states.json` (MAZ-62): the data state, appearances and failure recipe for each of the 61 redesign cards, and recorded/projected totals. Each totals case names its clock, time zone and local `today`; `dana-2026-10` (scenario `future-income`, MAZ-136) has income dated after today in `expected`, checked by TypeScript, Swift and the C# `FullStackSeedTests`.
- `fixtures/manifest.json` (MAZ-62): SHA-256 and consumers of every fixture; regenerate it (`npm run fixtures:generate`) after any fixture edit. TypeScript, C# and Swift verify the hashes.
- `swift/` (MAZ-62): the `PennyContracts` Swift package (strict `Codable` fixture models, loader, manifest hashes) for the native app.
- `design-baseline.json` (MAZ-132): traces for the 61 `docs/design/penny-ios` cards and 42 `design-kit` controls, tokens, navigation and legacy route map, decisions, behavior issues and source hashes. Visual comparison of implementations remains MAZ-122.

Run `npm run test:core`, `npm run test:ui`, `npm run lint`, `npm run typecheck` and `npm run fixtures:check`; `npm run test:fullstack` and `swift test --package-path contracts/swift` cover the full-stack environment and Swift ([test environment](../docs/migration/test-environment.md)). Validate the document with `npm exec --yes --package @redocly/cli@2.76.0 -- redocly lint contracts/openapi.json` (also in CI). The lightweight fixture matcher covers this document's exercised subset; it is not a general JSON Schema validator. Fixtures are consumed through strict typed models in C#, Swift and TypeScript, and old/new real HTTP behavior is compared by the `differential` scenario (MAZ-62).

No production credentials/data belong here. Synthetic addresses use `.test`; ephemeral generated sessions are never fixture credentials. Change OpenAPI, fixtures, drift tests and [compatibility documentation](../docs/migration/api-reference.md) together. See [architecture](../docs/migration/architecture.md), [PostgreSQL recovery](../docs/migration/postgresql.md), [search](../docs/migration/search.md) and [verification](../docs/migration/verification.md).
