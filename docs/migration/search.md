# Search v1 contract (MAZ-121)

`POST /api/v1/search/transactions` is additive and planned, marked `x-implementation: planned` in [OpenAPI](../../contracts/openapi.json). Node does not implement it. Existing ledger/projection routes and local substring selectors continue working. New clients use local substring on 404; do not infer search capability from `/api/info`'s version or require a new field there.

## Request and matching

Example: `{"query":"coffee","period":{"month":"2026-11"},"kind":"expense","mode":"substring","sort":"date-desc","pageSize":50}`. Require exactly one month (2000-01..2100-12) or year (2000..2100). Optional `day` is a full date within that period. Kind defaults to all (expense/income/investment also allowed). Query defaults empty, trims ECMAScript whitespace, max 200 UTF-16 code units. PageSize defaults 50, range 1..100. Optional opaque cursor is at most 2048 characters. Unknown keys/invalid combinations return 400; missing session 401, denied origin 403, stale cursor 409, body overflow 413, rate limit 429, timeout/unavailable 503 with Retry-After, unexpected failure 500. Every error uses `{error:string}`. Cancellation propagates to SQL. POST keeps text out of URL access logs; disable body/SQL parameter logging too.

Search recorded personal entries plus caller-authorized shared personal projections. Exclude scheduled previews, reimbursements, receipts/OCR and others' private entries. Fields: title, note, category label and **viewer-visible** account label. The document is exactly `${title} ${note} ${categoryName} ${accountName}` (missing labels empty), preserving legacy cross-field/punctuation matches. Bind query parameters and escape LIKE `%`, `_` and backslash as literals.

`mode=substring` (default) applies ECMAScript `toLowerCase()` to document/query then literal substring. No locale, accent stripping, Unicode normalization or stemming. Prepare canonical text in the application, store with deterministic C collation, and do not substitute database locale-sensitive lower/ILIKE. C#/Swift must pass Unicode fixtures (dotted I, Greek final sigma, composed/decomposed accents, ß); runtime/Unicode changes require fixture review and projection rebuild.

`mode=hybrid` adds `to_tsvector('english',document) @@ plainto_tsquery('english',query)` using OR with substring. English stemming/stop words are fixed for v1; other languages retain substring. No language detection, unaccent, fuzzy similarity, raw tsquery operators or external cluster. Empty query returns all filtered entries; punctuation-only/stop-word queries still use substring when tsquery has no lexemes. See [PostgreSQL parsing rules](https://www.postgresql.org/docs/18/textsearch-controls.html).

Both modes default to `sort=date-desc`: date descending, raw ID ascending in UTF-8 ordinal order, source personal/shared as final tie. This explicitly standardizes cross-runtime equal-date ties (legacy used localeCompare) while preserving chronological Activity. No relevance sort in v1. Deduplicate by `key` (`personal:<id>` / `shared:<expenseId>`), never title.

## Pagination and isolation

Response: `{version:1,scope:"server-recorded",ledgerRevision,searchRevision,items:[{key,source,entry}],totalCount,nextCursor}`. Entry uses existing Entry or ProjectedExpense; shared money stays totalCents/shareCents. No snippets/additional account labels. Count the authorized filtered union exactly once; totalCount is not a financial total. Summary cards remain independent of query/kind/day and label projected income separately.

Use one repeatable-read transaction for generation/revisions, authorization/period/kind/day filtering **before** matching/counting/pagination, and ordered results. Keyset cursor binds authenticated viewer, query/filter/mode/sort/pageSize hash, projection generation, searchRevision and final tuple; authenticate/sign it and expire after 15 minutes. Tampered/foreign/changed-query/expired cursors return 400. Valid cursors with changed data/visibility generation return 409; clients discard pages/restart. Relevant writes/rebuilds bump searchRevision. Always recheck current and historical visibility, including former members' permitted history. No stale cursor may restore access or leak counts. Never accept a caller-provided user ID.

GIN indexes cover tsvector and canonical text (`gin_trgm_ops`); B-tree keys cover viewer/date/ID/source. Short/common patterns may scan authorized rows because trigrams cannot prune them: preserve correctness, no silent three-character minimum. Bound SQL to 2s; apply 30 requests/minute/session. MAZ-121 retains EXPLAIN (ANALYZE, BUFFERS) and p95 evidence at 100k personal entries/viewer with shared-membership skew, cold/warm, short/common/selective queries and concurrent writes. Acceptance budgets: p95 <=300ms warm selective pages and <=1s nonselective/count on a documented reference host. These are targets, not measurements.

## Pending, offline and demo

While personal edits are pending, use **one complete local substring result set** from durable `local` plus cached authorized recorded shared projections. Label “On this device · pending changes”; disable server hybrid until synced. Do not overlay pending rows on server pages/counts: edits can stop matching, deletions suppress hits and creations change pages. Sync serially, refresh ledger/shared projection, discard old pages and switch the entire source. Conflicts follow ADR 002.

Offline uses local substring labeled “On this device · shared data last updated …”. Cached membership is last-known; clear known revoked data and reauthorize on reconnect. No durable data means unavailable, not “no matches”. Hybrid requires connectivity. Demo searches only its temporary in-memory sample, never the server. Summary definitions remain stable across result sources. MAZ-73/88 implement states; MAZ-71/87 verify pending create/edit/delete, reconnect and account/server switches using [fixtures](../../contracts/fixtures/search-cases.json).
