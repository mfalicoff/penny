Bundle DM Sans and its OFL license in each replacement client (MAZ-69/85); preserve scale/weights and support user text scaling rather than fixed storyboard metrics.

Native iOS 26 Liquid Glass is a **strict requirement** for floating tabs, toolbar controls, search, selection and primary actions. SwiftUI uses the real system material; Penpot blur/highlight values are static approximations. Financial content stays legible and opaque where appropriate. Reduced transparency uses opaque high-contrast surfaces; reduced motion avoids unnecessary transitions. AMOLED can use solid surfaces for its black appearance; document the exception in visual acceptance. MAZ-66 fixes minimum OS support before builds; if iOS below 26 is supported, use an explicit frosted/opaque adaptation and test it separately, never claim it is native Liquid Glass. Web uses accessible DOM/CSS materials with visible keyboard focus and reduced-motion/transparency adaptations.

## Screen coverage and limits

Every specimen has a native/web feature owner and planned MAZ-82/96 acceptance scenario in the JSON matrix. The 26 controls belong to MAZ-69/85 and the same acceptance gates. `home-android` is **legacy/reference only** under MAZ-98, never a new Android implementation requirement. Details/pickers/confirmations can be native sheets or nested web routes; do not turn every specimen into a new public URL. Preserve `/`, `/transactions`, `/entries/new`, account/category/recurring, household/trip detail and `/auth/callback` deep links.

Adapt the 390px frames to safe areas, iPhone landscape, iPad split/multicolumn and resizable browser layouts. Proposed web breakpoints: <768 one column, 768–1099 compact rail/two columns, >=1100 sidebar/grid; validate 320px through desktop rather than copying fixed geometry. Test Dynamic Type/VoiceOver, keyboard/focus, scrolling above Save, contrast on changing backdrops, reduced motion/transparency and native pickers. These are acceptance requirements, not evidence of device execution.

The local report records 79 destinations with no declared broken targets or containment violations. **Native Penpot validation failed with 89 unmatched-node findings** after partial material/category synchronization. MAZ-122 must explain validator discrepancies versus missing design work, complete sync without changing stable board IDs, and publish new evidence. Static inputs, representative detail links and screenshot contrast samples are not exhaustive functional/accessibility tests. iPad, larger text, actual keyboard/focus, native picker/lock and PostgreSQL search/loading/offline behavior still require implementation validation. MAZ-82/96 cannot substitute storyboard checks for these gates.
